## Projects

### 1. Linux Administration and Hardening

**Goal:** Configure and document a Linux server using practical
administration and security practices.

Planned topics: - System baseline and service inventory - SSH access and
security settings - User, group, and file-permission management - Host
firewall configuration - Nginx service deployment - Logs, disk usage,
and basic monitoring - Bash scripts for routine administration

**Evidence:** Configuration files, command output, verification steps,
and troubleshooting notes.

### 2. AWS Infrastructure

**Goal:** Design and test a basic AWS environment while applying secure
access and cost-awareness practices.

Planned topics: - VPC and subnet design - Route tables and Internet
Gateway - Security groups and network ACL concepts - EC2 access and
instance security - IAM least-privilege policies - Private S3 storage
and versioning - Resource cleanup and cost checks

**Evidence:** Architecture diagram, configuration notes, policy
examples, and test results. Label any resources only designed on paper
as conceptual.

### 3. Enterprise Network Simulation

**Goal:** Build a small company network in Cisco Packet Tracer and test
connectivity and access controls.

Planned topics: - IP addressing and subnet planning - VLANs and trunk
links - Inter-VLAN routing - DHCP and DNS - Access control lists
(ACLs) - Spanning Tree Protocol fundamentals - Connectivity testing and
fault diagnosis

**Evidence:** Packet Tracer `.pkt` file, topology diagram, device
configurations, and successful and failed test results.

### 4. Windows Administration Fundamentals

**Goal:** Practice core Windows support and administration tasks.

Planned topics: - Local user and group management - Shared folders and
NTFS permissions - Services and Event Viewer - Basic network
troubleshooting - Active Directory and Group Policy concepts

**Evidence:** Notes and screenshots from tasks that have actually been
completed.

### 5. Hybrid Infrastructure Capstone

**Goal:** Explain how an on-premises company network and cloud
infrastructure can work together.

This capstone brings together the network simulation, Linux services,
and AWS architecture. It includes a combined diagram, traffic-flow
explanation, security considerations, and troubleshooting scenarios.

Any site-to-site VPN connection or integration that is only described in
the design will be labeled **conceptual**, not presented as deployed.

### 6. Troubleshooting Tickets

Each ticket follows a consistent format:

1.  **Problem:** What happened?
2.  **Impact:** What was affected?
3.  **Investigation:** Which checks and commands were used?
4.  **Root cause:** What caused the problem?
5.  **Resolution:** What change fixed it?
6.  **Verification:** How was the fix confirmed?
7.  **Prevention:** How could the issue be avoided?

## How I Document and Test Work

For each project, I aim to include:

-   The objective and environment
-   A diagram or configuration overview
-   Steps to reproduce the setup
-   Commands and configuration files
-   Tests demonstrating expected behavior
-   Problems encountered and how they were resolved
-   Security and cost considerations
-   Lessons learned and possible improvements

A screenshot alone is not proof that a system works. Where possible, I
include test commands and their actual results.

## Security and Cost Practices

-   Never commit passwords, private keys, access tokens, or AWS
    credentials.
-   Use least-privilege access wherever practical.
-   Restrict administrative access to trusted sources.
-   Keep test systems isolated and use only systems I am authorized to
    administer.
-   Check AWS pricing before deploying resources.
-   Review billing and remove unused billable resources after testing.
-   Do not treat billing alerts as spending limits.
-   Redact sensitive information from screenshots and logs.
